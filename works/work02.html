DirectX11 フレームワーク

  • C++
  • DirectX11
  • HLSL
  • PMX / VMD
  • Jolt Physics
動画（仮）

C++20 と DirectX11 で作った、ゲーム作りのための自作のフレームワークです。コードで GameObject と Component を組んでゲームを作る形にし、MMD のキャラクターの表示とアニメーション、影やポストエフェクトなどの描画、物理、画面の UI と文字、開発を助けるデバッグの道具を作りました。

エンジンの設計

層の分け方と 1 フレームの流れ

エンジンを 7 つの層に分け、下の層は上の層を知らない形にしました。ゲームのコードは Scene の層から使い、描画の層とは、描く物の一覧などの決まった口だけでやり取りします。

  • 層: Utility → Platform → Graphics → Render → Scene → DebugTools → Core（下から順。Core がすべてを組み立てる）
  • Direct3D 11 の型は Graphics と Render の層の中だけで使い、ゲームのコードには出さない
  • 1 フレームの流れ: 入力 → 時刻 → 固定ステップの物理 → Update → コルーチン → LateUpdate（モーション、揺れもの、スキン）→ 作る・消すの確定 → 音 → 描く物の収集 → 描画

Scene・GameObject・Component

コードで GameObject を作って Component を付け、場面を組み立てます。Component は OnStart・FixedUpdate・Update・LateUpdate などを持ち、フレームの途中で作った物や消した物は、フレームの区切りでまとめて確定します。

  • 標準の Component: カメラ、ライト、MeshRenderer、Rigidbody、Collider、Animator、ParticleEmitter、AudioSource、UiImage、UiText など
  • Scene の切り替えはフレームの頭の 1 か所だけで行い、フレームの途中で頼んでも、そのフレームは前の Scene のまま最後まで動く
  • 固定ステップの回数に上限を設け、重いフレームでも止まらないようにした
// Scene の OnLoad の中で、火花の粒を出す GameObject を作る
Engine::GameObject& sparks = CreateObject("Sparks");
sparks.GetTransform().SetLocalPosition(Engine::Vector3(0.0f, 1.0f, 2.0f));
Engine::ParticleEmitter& emitter = sparks.AddComponent<Engine::ParticleEmitter>();
emitter.SetEmissionRate(60.0f);                              // 毎秒 60 個
emitter.SetAcceleration(Engine::Vector3(0.0f, -9.8f, 0.0f)); // 重力

描画

描画のパスの流れ

描画は、役目ごとに分けたパスを決まった順に並べて行います。パスの前に、頂点モーフの差分を GPU に写し、影の段の範囲を決めます。ゲームのコードから自分のパスを足すこともできます。

  1. ShadowPass: 影の絵を描く
  2. SceneTargetPass: ポストエフェクトを使うとき、16 ビットの浮動小数の的に切り替える
  3. OpaquePass: 不透明の物を描く
  4. SkyPass: 何も描かれていない画素に空を描く
  5. OutlinePass: 輪郭線を描く
  6. TransparentPass: 半透明の物を、カメラから遠い順に描く
  7. ParticlePass: 粒を描く
  8. PostEffectPass: ブルーム、トーンマップ、ディザ、FXAA を掛けて画面に出す
  9. SpritePass: 画面の UI と文字を描く
  10. DebugLinePass、ImGuiPass: デバッグの線と ImGui の窓を描く（Debug 構成だけ）

カスケードシャドウマップ

平行光源の影を、カメラから決めた距離までを最大 4 つの段に分けたシャドウマップで付けます。近い段ほど細かい影の絵を使うので、手前の影をくっきりさせたまま、遠くまで影を落とせます。

  • 2048×2048 の影の絵を 4 つに分けて使い、影の縁は 3×3 の PCF でやわらげる
  • 深度と法線の向きのずらしを、影の絵の 1 テクセルを単位にして決める
  • 影の距離の最後の 1 割で影を薄め、影の端が急に切れないようにした
  • Toon の物は、影の所がトゥーンのテクスチャの暗い色になる（MMD のセルフ影の見え方）
  • 骨とモーフで動く PMX のモデルは、動いた形の影を落とす
  • デバッグの窓で、段ごとに色を付けて範囲を確かめられる

光と陰影

平行光源 1 つと、点光源とスポットを場面の全体で 16 個まで置けます。標準のシェーダーは Lit と Toon の 2 つで、Lit はランバート、Toon はトゥーンのテクスチャで陰を付けます。

  • 点光源とスポットは、光ごとに拡散と反射を足す（範囲の端で滑らかに 0 になる減衰と、スポットの角度の減衰）
  • 段の付いた反射: Blinn-Phong の反射を、硬い段となだらかな段で切って、アニメ調のハイライトにする
  • リム: 視線と面の向き（N·V）から、輪郭に近い所を光らせる
  • 発光: Material ごとの強さとマスクで光らせ、ブルームでにじませる

トゥーン・スフィア・輪郭線

MMD のモデルの見た目に合わせて、トゥーンのテクスチャで付ける陰、スフィアマップ、輪郭線を描けるようにしました。PMX のモデルは、材質の値からこれらを設定します。

  • スフィアマップは、色を足す形と掛ける形の 2 つ
  • 輪郭線: 頂点を法線の向きに押し出した殻の、裏の面だけを描く。どのシェーダーの Material にも付けられる
  • 押し出す向きに、同じ位置の頂点の法線を平均した向きも選べ、箱の角や円柱の縁でも線が切れない
  • PMX の頂点ごとのエッジの倍率で、場所ごとに線の太さを変える

半透明と切り抜き

不透明の物を描いた後に、半透明の物を物ごとにカメラから遠い順に並べ、後ろの色と混ぜて描きます。

  • 切り抜き: テクスチャのアルファで穴を開ける。影も穴の形になる
  • 両面: Material ごとに裏の面も描ける
  • テクスチャに透ける画素がある材質は、読み込むときに半透明の描き方にする

ポストエフェクト

カメラごとにポストエフェクトを付けられます。使うときは、場面を 16 ビットの浮動小数の的に描いて 1 を超える明るさを残し、効果を掛けてから画面に出します。

  • ブルーム: 明るさが閾値を超えた所を、5 段のにじみで周りに広げて足す
  • トーンマップ: 露出を掛けた後、明るい所を 1 に近づくように、肩の曲線でなめらかに縮める
  • ディザ: 8 ビットに丸める前に、画素の位置で決まる小さな揺らぎを足し、なだらかな所の縞を消す
  • FXAA: 輝度の差で縁を見つけ、縁に沿って読み直して、斜めの縁のぎざぎざを和らげる
  • 画面の UI と文字、デバッグの表示は効果の後に描くので、にじまない

手続きの空

カメラに Component を付けると、光の向きにそろった太陽のある空を描きます。大気の散乱を簡単にした式を画素ごとに計算し、地平線より下は地面の色にします。

  • 物が描かれていない画素だけを塗るので、物の後ろの画素は計算しない
  • 太陽の位置は平行光源の向きから決まり、光を回すと空の色も変わる

パーティクル

ParticleEmitter の Component で粒を出し、CPU で動かして、カメラを向く板にして描きます。

  • 毎秒の数、寿命、速さ、出す向きの円錐、加速度、減衰、大きさと色の変化を設定できる
  • 混ぜ方は、加算（火花など）とアルファ（煙など）の 2 つ。アルファの粒は、カメラから遠い順に並べて描く
  • 粒はワールドの空間に置くので、出した後に出す物を動かしても、粒はその場で動き続ける
  • 乱数の種を決めれば、同じ動きを何度でも再現できる

画面の UI と文字

画面に重ねる 2D の画像（UiImage）と字（UiText）を、アンカーと基準の解像度で置きます（Unity の RectTransform と Canvas Scaler と同じ考え方）。ポストエフェクトの後に描くので、UI はにじみません。

  • 層と層の中の順で重なりを決め、同じテクスチャの四角が続く所はまとめて 1 回で描く
  • マウスが四角の中にあるかを調べられ、ボタンに使える
  • 字は、Windows の字体を DirectWrite で開き、使う字だけを SDF にしてアトラスに入れる（日本語も出る）
  • 行送り、揃え、折り返し、簡単な禁則で並べ、縁取りを付けて描く

MMD のキャラクター

PMX の読み込み

MMD のモデルの形式 PMX（2.0 と 2.1）を読み込みます。頂点、材質、骨、モーフ、剛体とジョイントを読み、材質の値（色、両面、テクスチャ、トゥーン、スフィア、輪郭線）を Material に入れます。

  • 頂点の重みは BDEF1・BDEF2・BDEF4 に対応（SDEF と QDEF は近い形にして読む）
  • テクスチャのパスは、サブフォルダや日本語の名前も読める
  • 壊れた節のあるファイルも、読める所までで表示する

骨とスキン

Animator の Component で骨のポーズを決め、骨の行列を使って頂点シェーダーでスキンして描きます。

  • FK と、ほかの骨の回転を受け継ぐ回転の付与
  • IK: 足の IK などを CCD で解く。ひざは 1 つの軸の角度の制限で曲げる
  • 骨とモーフで動いた形には、輪郭線と影も付いてくる

モーフ

頂点モーフ、材質モーフ、グループモーフで表情を変えます。

  • 頂点モーフは、重みを掛けた差分を、頂点シェーダーでスキンの前に足す
  • 重みが変わったフレームだけ差分を作り直して GPU に写す
  • 材質モーフは、色などを足す形と掛ける形に対応

VMD のモーション

MMD のモーションの形式 VMD を読み込み、骨と表情を時間に沿って動かします。

  • キーの間は VMD の補間曲線（3 次ベジェ）で補い、回転は球面線形補間で補う
  • IK の on と off のキーにも対応
  • 負の速さで逆に再生できる
  • 2 本のモーションを、決めた秒数で混ぜて切り替える（クロスフェード）

揺れもの

PMX の剛体とジョイントを物理エンジンの Jolt Physics に写し、髪やスカートを揺らします。モデルの値を Jolt の剛体とジョイントに写す所と、骨との受け渡しを作りました。

  • 骨に付いて動く剛体と物理で動く剛体を分け、物理の結果を骨に戻す
  • ジョイントの移動と回転の制限、ばねを写す
  • 当たりのグループ（16 のグループとマスク）を、Jolt の層の値に詰めて写す
  • モーションを止めている間も、毎フレーム物理を進める

ゲームの仕組み

物理

ゲームの物の動きと当たり判定の物理は、自分で作りました（揺れものの Jolt Physics とは別）。

  • Rigidbody: 重力と速度で動かす。Kinematic の物で押せる
  • Collider: 球・箱・カプセル。衝突と Trigger のコールバック
  • 重なりの押し戻しで、箱を積み重ねられる
  • 問い合わせ: レイを当てて最も近い 1 つを返す、形を重ねて当たる物を集める（球・箱・カプセル）、画面の点（マウス）からのレイを作る

コルーチンと Tween

C++20 のコルーチンで、待ってから動く処理や演出の流れを、状態の変数を持たずに 1 つの関数の中に順に書けるようにしました。

  • co_await で、秒（時間の倍率あり・なし）、フレームの数、条件、子のコルーチンを待つ
  • Component が止まっている間は進まず、Component を消すときに一緒に壊す
  • Tween: 数、ベクトル、回転（Quaternion）を時間で動かすコルーチンの関数。イージングの曲線は 30 種
Engine::Coroutine Blink() {
    for (;;) {
        co_await Engine::WaitForSeconds(2.0f); // 時間の倍率を掛けた 2 秒
        SetLit(false);
        co_await Engine::WaitForFrames(3);     // 3 フレーム
        SetLit(true);
    }
}

サウンドと入力

Windows の XAudio2 で WAV を鳴らします。AudioSource と AudioListener の Component で、聞き手との位置から 3D の音にします。

  • 主の音量と、BGM と効果音のバスで、音量を分けて変えられる
  • 入力: キー、マウス、XInput のパッド 4 台（ボタン、スティック、トリガー）を、同じ口で読む
  • カメラの操作: Unity の SceneView のように、マウスとキーボードでカメラを動かす Component

資産の管理と基本形状

AssetManager で、テクスチャ、モデル、モーション、音、字体を読み込みます。読んだ物は取っておき、同じファイルを使う物どうしで共有します。

  • テクスチャ: Windows の WIC で読める形式（PNG、JPEG、BMP など）
  • モデル: OBJ と .mtl（材質ごとのサブメッシュと Material）、PMX
  • 基本形状: 立方体、球、カプセル、円柱、平面、トーラスの Mesh を、ファイルを読まずにコードで作る

開発の道具

デバッグ機能

Debug 構成では、Dear ImGui で作った窓から、場面の中身を見て、その場で直せます。

  • 階層とインスペクター: GameObject の有効、Transform、Component の値を直す
  • ギズモ: 選んだ物を、画面の取っ手で動かす・回す・大きさを変える（ワールドとローカルの軸、Ctrl で刻む）
  • コードとしてコピー: 直した値を、ソースに貼れる形でクリップボードに入れる
  • 資産の窓: 読んだ資産の持ち主の数と読んだ回数、テクスチャの縮小と読み直し、音の試し
  • デバッグの線: Collider の形などを線で描く
  • 窓の言葉を、日本語と英語で切り替えられる

シェーダーの読み直し

標準のシェーダーの .hlsl を直して F5 を押すと、アプリを止めずに新しいシェーダーで描きます。すべてのシェーダーをコンパイルでき、C++ の側と食い違わないときだけ入れ替えるので、途中で書き間違えても絵は壊れません。

描画の確かめの道具

描画を確かめるための道具は、Release 構成にも入れています。

  • パスごとの GPU のマーカー: RenderDoc で 1 フレームを撮ると、パスの名前が描く順に並ぶ
  • スクリーンショット: そのフレームの全部のパスを描いた後の画面を PNG に書く
  • 絵の比べ: 時刻を 1/30 秒ずつに固定して撮った絵を、基準の絵と 1 画素ずつ比べ、描画の変化を見つける
